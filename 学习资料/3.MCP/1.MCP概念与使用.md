# MCP 协议（选学）

> MCP（Model Context Protocol）是 Anthropic 推出的开放协议，让 AI 模型能直接调用外部工具和数据源。
> 理解 MCP 有助于你理解 Agent 的"工具调用"底层原理，面试中了解即可。
> 本节为选学内容，不影响主线学习。

---

## 一、MCP 是什么？

### 1.1 一句话理解

MCP = **AI 模型和外部工具之间的"USB 接口标准"**。

以前每个 AI 应用要接一个工具（读文件、查数据库、调 API），都要自己写一套对接代码。MCP 定义了一个统一标准，让所有工具按同一格式暴露能力，所有 AI 都能直接用。

### 1.2 类比理解

```
没有 MCP 的世界（以前）：
  Claude 要读文件 → 写专门的文件读取代码
  Claude 要查数据库 → 写专门的数据库代码
  Claude 要调天气 API → 写专门的天气代码
  每个工具都要写一套适配代码，累死

有了 MCP 的世界（现在）：
  MCP Server（文件系统）──┐
  MCP Server（数据库）────┤──→ MCP 协议 ──→ Claude / 任何 AI
  MCP Server（天气 API）──┘
  所有工具用同一个标准，即插即用
```

就像 USB 统一了各种设备的接口。

### 1.3 核心架构

```
┌──────────┐     MCP 协议     ┌──────────────┐
│  MCP     │ ←──────────────→ │  MCP         │
│  Client  │   JSON-RPC 通信   │  Server      │
│ (AI侧)  │                  │ (工具侧)      │
└──────────┘                  └──────────────┘
   Claude                     文件系统/数据库/API
   VS Code                    任何外部服务
   你的应用
```

**MCP Client**：AI 那边，发出"我要读文件"的请求
**MCP Server**：工具那边，接收请求、执行操作、返回结果
**协议**：JSON-RPC 格式，定义了怎么描述工具、怎么调用、怎么返回

## 二、MCP 的三大能力

### 2.1 Tools（工具）

让 AI 调用外部功能：

```json
{
  "name": "read_file",
  "description": "Read the contents of a file",
  "inputSchema": {
    "type": "object",
    "properties": {
      "path": {"type": "string", "description": "File path to read"}
    },
    "required": ["path"]
  }
}
```

AI 看到这个描述就知道：有个 `read_file` 工具，传一个 `path` 参数就能读文件。

### 2.2 Resources（资源）

让 AI 读取外部数据源（文件、数据库记录等），类似 GET 请求。

### 2.3 Prompts（提示模板）

预定义的 Prompt 模板，让 AI 在特定场景下使用。

---

## 三、MCP Server 的工作方式

### 3.1 通信方式

MCP 有两种通信方式：

| 方式 | 原理 | 适合场景 |
|------|------|---------|
| **stdio** | 通过标准输入/输出通信 | 本地工具（文件系统、计算器）|
| **SSE** | 通过 HTTP Server-Sent Events | 远程服务（数据库、Web API）|

### 3.2 生命周期

```
1. Client 发起连接
2. Client 和 Server 交换能力信息（"你能做什么？""我有这些工具"）
3. Client 根据需要调用 Server 的工具
4. Server 执行操作，返回结果
5. 连接保持，可以反复调用
```

## 四、在 Claude Desktop 中使用 MCP

### 4.1 配置 MCP Server

Claude Desktop 的配置文件位置：
- **Windows**: `%APPDATA%\Claude\claude_desktop_config.json`
- **Mac**: `~/Library/Application Support/Claude/claude_desktop_config.json`

```json
{
  "mcpServers": {
    "filesystem": {
      "command": "npx",
      "args": [
        "-y",
        "@modelcontextprotocol/server-filesystem",
        "E:\\projects"
      ]
    }
  }
}
```

配置后重启 Claude Desktop，它就能直接读写 `E:\projects` 目录下的文件。

### 4.2 常用官方 MCP Server

| Server | 功能 | 安装命令 |
|--------|------|---------|
| filesystem | 读写本地文件 | `npx @modelcontextprotocol/server-filesystem /path` |
| sqlite | 操作 SQLite 数据库 | `npx @modelcontextprotocol/server-sqlite db.sqlite` |
| github | 操作 GitHub 仓库 | 需要配置 Token |
| fetch | 抓取网页内容 | `npx @modelcontextprotocol/server-fetch` |

## 五、用 Python 写 MCP Server

### 5.1 核心思路

用 `mcp` Python SDK 定义一个 Server，声明它提供的工具，然后实现每个工具的逻辑。

```python
from mcp.server import Server
from mcp.types import Tool, TextContent

server = Server("my-server")

@server.list_tools()
async def list_tools():
    return [
        Tool(
            name="get_weather",
            description="Get weather for a city",
            inputSchema={...}
        )
    ]

@server.call_tool()
async def call_tool(name, arguments):
    if name == "get_weather":
        city = arguments["city"]
        # 调用天气 API...
        return [TextContent(type="text", text=f"{city}: 25°C, sunny")]
```

### 5.2 关键概念

- `@server.list_tools()`: 告诉 Client "我有哪些工具"
- `@server.call_tool()`: Client 调用工具时执行的逻辑
- `inputSchema`: JSON Schema 格式，定义工具参数的类型和规则
- 返回 `TextContent`: 工具执行结果

## 六、MCP 和你项目的关系

### 6.1 和 Agent 的关系

MCP 的 Tools 概念和 Agent 的工具调用（Function Calling）本质上是同一件事：

```
Agent (Day 31-37 会学):
  LLM → 决定调用什么工具 → Function Calling → 执行工具 → 返回结果

MCP:
  LLM → 决定调用什么工具 → MCP Protocol → MCP Server 执行 → 返回结果
```

区别在于：
- Function Calling 是一次性的接口定义
- MCP 是持久化的协议标准，工具以独立服务运行

### 6.2 你现在需要深入学 MCP 吗？

**不需要**。理由：
1. 你的项目用 LangChain/LangGraph 的工具系统就够了
2. MCP 更多是"平台侧"的事（Claude Desktop、VS Code 用 MCP 连接工具）
3. 面试中了解概念即可，不会深入问实现

### 6.3 什么时候要深入 MCP？

- 入职后公司要做 AI 平台/AI 工具集成
- 想给 Claude Desktop 加自定义能力
- 想做一个通用的 AI 工具市场

## 七、面试怎么回答

> **问：你了解 MCP 吗？**
>
> MCP 是 Anthropic 推出的 Model Context Protocol，是 AI 模型和外部工具之间的标准通信协议。
> 它定义了 Client-Server 架构，通过 JSON-RPC 通信，让 AI 能以统一的方式调用文件系统、
> 数据库、API 等外部工具。核心能力包括 Tools（工具调用）、Resources（资源读取）和
> Prompts（提示模板）。它和 Function Calling 解决的是同一类问题，但 MCP 是协议级别的标准化。
