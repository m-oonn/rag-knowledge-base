## 一、装饰器（Decorator）

### 1.1 装饰器是什么？

**一句话理解**: 装饰器就是一个函数，它接收一个函数作为参数，返回一个新函数，用来在**不修改原函数代码**的情况下给它加功能。

现实类比：你有一杯咖啡（原函数），装饰器就是往里面加奶（加功能），咖啡本身没变，但喝起来不一样了。

### 1.2 为什么需要装饰器？

假设你有 10 个函数，都需要记录执行时间。你有两个选择：
- **笨办法**: 在每个函数里都加一段计时代码（重复 10 次）
- **聪明办法**: 写一个装饰器，往每个函数头上加一行 `@计时` 就行

### 1.3 装饰器的原理

```python
# 装饰器的本质就是这个过程：
def my_decorator(func):       # 1. 接收原函数
    def wrapper(*args, **kwargs):  # 2. 定义一个新函数
        print("函数执行前")
        result = func(*args, **kwargs)  # 3. 在新函数里调用原函数
        print("函数执行后")
        return result
    return wrapper              # 4. 返回新函数

# 用 @ 语法糖
@my_decorator
def say_hello(name):
    print(f"Hello, {name}")

# 等价于：say_hello = my_decorator(say_hello)
```

### 1.4 装饰器执行流程图

```
调用 say_hello("张三")
        │
        ▼
  进入 wrapper()        ← 装饰器的新函数
        │
        ├─ print("函数执行前")
        │
        ├─ 调用原始 say_hello("张三")
        │       └─ print("Hello, 张三")
        │
        ├─ print("函数执行后")
        │
        └─ 返回结果
```

### 1.5 带参数的装饰器

有时候装饰器本身也需要参数，比如 `@repeat(3)` 表示重复执行 3 次：

```python
def repeat(times):                  # 最外层：接收装饰器的参数
    def decorator(func):            # 中间层：接收被装饰的函数
        def wrapper(*args, **kwargs):  # 最内层：实际执行逻辑
            for _ in range(times):
                result = func(*args, **kwargs)
            return result
        return wrapper
    return decorator

@repeat(3)
def greet(name):
    print(f"Hi, {name}")
```

**记忆口诀**: 三层嵌套 —— 参数层 → 函数层 → 执行层

### 1.6 `functools.wraps` —— 保留原函数信息

装饰器有个小问题：装饰后函数的名字变成了 `wrapper`，调试时很混乱。用 `@functools.wraps` 解决：

```python
from functools import wraps

def my_decorator(func):
    @wraps(func)  # 加这一行，保留原函数的名字和文档
    def wrapper(*args, **kwargs):
        return func(*args, **kwargs)
    return wrapper
```

### 1.7 FastAPI 中的装饰器

FastAPI 重度使用装饰器，你每天都会见到：

```python
@app.get("/users/{user_id}")    # 路由装饰器
@app.post("/items/")            # 路由装饰器
@app.middleware("http")         # 中间件装饰器
```

理解了装饰器原理，这些就不再是"魔法"了。

### 1.8 常见内置装饰器

| 装饰器 | 作用 | 常用场景 |
|--------|------|---------|
| `@staticmethod` | 静态方法，不需要 self | 工具函数 |
| `@classmethod` | 类方法，第一个参数是 cls | 工厂模式 |
| `@property` | 把方法变成属性访问 | getter/setter |
| `@functools.lru_cache` | 缓存函数结果 | 重复计算优化 |

## 二、类型注解（Type Hints）

### 2.1 类型注解是什么？

Python 是动态类型语言，变量不需要声明类型。类型注解就是**给代码加上类型标签**，告诉别人（和工具）这个变量应该是什么类型。

```python
# 没有类型注解 —— 看不出参数和返回值是什么类型
def add(a, b):
    return a + b

# 有类型注解 —— 一目了然
def add(a: int, b: int) -> int:
    return a + b
```

**重要**: 类型注解**不会**在运行时强制检查，它只是"标签"。但 FastAPI 和 Pydantic 会利用类型注解做**自动数据验证**。

### 2.2 为什么 FastAPI 必须懂类型注解？

FastAPI 的核心就是基于类型注解：

```python
@app.get("/users/{user_id}")
def get_user(user_id: int):  # FastAPI 自动把 URL 参数转成 int
    return {"user_id": user_id}

# 如果访问 /users/abc，FastAPI 自动返回 422 错误（类型不对）
```

没有类型注解，FastAPI 就无法工作。

### 2.3 基础类型注解

```python
# 变量注解
name: str = "张三"
age: int = 21
score: float = 95.5
is_student: bool = True

# 函数注解
def greet(name: str, times: int = 1) -> str:
    return f"Hello, {name}!" * times
```

### 2.4 复合类型注解

```python
from typing import List, Dict, Optional, Tuple, Union

# 列表（里面全是字符串）
names: list[str] = ["张三", "李四"]

# 字典（键是字符串，值是整数）
scores: dict[str, int] = {"数学": 90, "英语": 85}

# 可选类型（可以是 str，也可以是 None）
nickname: str | None = None     # Python 3.10+ 写法
nickname: Optional[str] = None  # 旧写法，效果一样

# 元组
point: tuple[float, float] = (3.14, 2.72)

# 联合类型（可以是 str 或 int）
user_id: str | int = "abc123"   # Python 3.10+
user_id: Union[str, int] = 123  # 旧写法
```

### 2.5 Pydantic 模型（FastAPI 的数据验证核心）

类型注解 + Pydantic = 自动数据验证：

```python
from pydantic import BaseModel

class User(BaseModel):
    name: str
    age: int
    email: str | None = None  # 可选字段，默认 None

# Pydantic 自动验证
user = User(name="张三", age=21)           # 正常
user = User(name="张三", age="不是数字")    # 报错！age 必须是 int
```

### 2.6 类型注解速查表

| 写法 | 含义 | 示例 |
|------|------|------|
| `x: int` | 整数 | `age: int = 21` |
| `x: str` | 字符串 | `name: str = "张三"` |
| `x: list[str]` | 字符串列表 | `tags: list[str] = []` |
| `x: dict[str, int]` | 字典 | `scores: dict[str, int] = {}` |
| `x: str \| None` | 可以为 None | `bio: str \| None = None` |
| `-> int` | 返回值类型 | `def add() -> int:` |

## 三、上下文管理器（Context Manager）

### 3.1 上下文管理器是什么？

**一句话理解**: 上下文管理器确保"用完之后一定会清理"，不管中间有没有出错。

最常见的例子就是文件操作：

```python
# 不用上下文管理器 —— 如果中间出错，文件可能不会被关闭
f = open("data.txt")
content = f.read()
f.close()  # 如果上面出错了，这行不会执行

# 用上下文管理器 —— 无论如何都会关闭文件
with open("data.txt") as f:
    content = f.read()
# 退出 with 块时，文件自动关闭（即使出错也会关闭）
```

### 3.2 为什么需要？

在 AI 应用开发中，你会频繁遇到需要"打开→使用→确保关闭"的场景：
- 文件操作（读写文档）
- 数据库连接（查询后要关闭连接）
- API 会话（HTTP 客户端）
- 临时目录/资源

### 3.3 with 语句的执行流程

```
with open("file.txt") as f:
    │
    ├─ 1. 调用 __enter__()  → 返回文件对象给 f
    │
    ├─ 2. 执行 with 块内的代码
    │       └─ content = f.read()
    │
    └─ 3. 调用 __exit__()   → 关闭文件（无论是否出错）
```

### 3.4 自定义上下文管理器（类方式）

```python
class Timer:
    """计时器上下文管理器"""
    def __enter__(self):
        import time
        self.start = time.time()
        return self  # with ... as xxx 中的 xxx 就是这个返回值

    def __exit__(self, exc_type, exc_val, exc_tb):
        import time
        self.elapsed = time.time() - self.start
        print(f"耗时: {self.elapsed:.2f}秒")
        return False  # False = 不吞掉异常，让它继续抛出

# 使用
with Timer() as t:
    # 做一些耗时操作
    sum(range(1000000))
# 输出: 耗时: 0.03秒
```

### 3.5 自定义上下文管理器（生成器方式，更简洁）

```python
from contextlib import contextmanager

@contextmanager
def timer():
    import time
    start = time.time()
    yield  # yield 之前 = __enter__，yield 之后 = __exit__
    elapsed = time.time() - start
    print(f"耗时: {elapsed:.2f}秒")

with timer():
    sum(range(1000000))
```

**记忆口诀**: `yield` 把函数劈成两半 —— 上半是进入，下半是退出。

### 3.6 实际应用场景

```python
# 1. 数据库连接（FastAPI 中非常常见）
@contextmanager
def get_db():
    db = SessionLocal()
    try:
        yield db
    finally:
        db.close()

# 2. 临时切换目录
@contextmanager
def temp_directory(path):
    import os
    old_dir = os.getcwd()
    os.chdir(path)
    try:
        yield
    finally:
        os.chdir(old_dir)

# 3. HTTP 客户端会话
import httpx
with httpx.Client() as client:
    response = client.get("https://api.example.com/data")
```

## 四、三者的关系（在 FastAPI 中）

```python
from functools import wraps
from fastapi import FastAPI, Depends
from pydantic import BaseModel

app = FastAPI()

# 【类型注解】定义数据模型
class Item(BaseModel):
    name: str
    price: float
    description: str | None = None

# 【上下文管理器】管理数据库连接
def get_db():
    db = SessionLocal()
    try:
        yield db  # FastAPI 的 Depends 会自动处理这个生成器
    finally:
        db.close()

# 【装饰器】定义路由 + 【类型注解】参数验证
@app.post("/items/")
def create_item(item: Item, db = Depends(get_db)):
    # item 自动经过 Pydantic 验证
    # db 由上下文管理器自动管理生命周期
    return {"name": item.name, "price": item.price}
```

**总结**: 装饰器定义路由，类型注解做数据验证，上下文管理器管理资源——三者在 FastAPI 中缺一不可。

## 五、面试常问

1. **装饰器的本质是什么？** → 一个接收函数、返回函数的函数（高阶函数）
2. **`@wraps` 有什么用？** → 保留被装饰函数的 `__name__` 和 `__doc__`
3. **类型注解会在运行时检查吗？** → 不会，只是标注。但 Pydantic/FastAPI 会利用它做验证
4. **`with` 语句的原理？** → 调用对象的 `__enter__` 和 `__exit__` 方法
5. **`yield` 在上下文管理器中的作用？** → 把函数分成进入和退出两部分
