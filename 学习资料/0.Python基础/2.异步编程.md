## 一、为什么需要异步？

### 1.1 一个真实场景

假设你在做一个 AI 问答系统，用户发来一个问题，你需要：
1. 查向量数据库（耗时 0.5 秒）
2. 调用大模型 API（耗时 3 秒）
3. 保存对话记录到数据库（耗时 0.2 秒）

**同步方式（一个一个排队）**：
```
用户A的请求: [查数据库 0.5s][调API 3s][存记录 0.2s] = 3.7秒
用户B的请求:                                          [查数据库 0.5s][调API 3s][存记录 0.2s]
                                                       ↑ 用户B等了 3.7秒才开始被处理！
```

**异步方式（等待时去处理别的）**：
```
用户A: [查数据库]---等待--->[调API]--------等待-------->[存记录]
用户B:           [查数据库]---等待--->[调API]--------等待-------->[存记录]
                 ↑ 用户A在等数据库响应时，CPU去处理用户B了！
```

### 1.2 同步 vs 异步的本质

| | 同步 | 异步 |
|--|------|------|
| 比喻 | 在餐厅排队，前面的人点完你才能点 | 服务员同时服务多桌，谁的菜好了先送谁 |
| 特点 | 一行一行执行，遇到等待就干等 | 遇到等待就切换去做别的事 |
| 适合 | CPU 密集（计算）| IO 密集（网络请求、文件读写、数据库查询）|
| FastAPI | `def` 同步路由 | `async def` 异步路由 |

### 1.3 关键概念：IO 密集 vs CPU 密集

**IO 密集型（异步大显身手）**：
- 调用大模型 API（等网络响应）
- 查询数据库（等数据库返回）
- 读写文件（等磁盘）
- 这些操作大部分时间在**等待**，CPU 是空闲的

**CPU 密集型（异步帮不了你）**：
- 计算 Embedding 向量
- 图片处理
- 大量数学运算
- CPU 一直在忙，没有"等待"的间隙

**记住**: 异步不是让代码跑得更快，而是让 CPU **在等待时去干别的事**。

## 二、async/await 基础

### 2.1 核心语法

```python
import asyncio

# 普通函数
def normal_function():
    return "我是普通函数"

# 异步函数（协程函数）
async def async_function():
    return "我是异步函数"
```

加了 `async` 关键字的函数就变成了**协程函数**（coroutine function）。

### 2.2 await —— "在这里可以切换"

`await` 的意思是：**这里要等一会儿，先让别人用 CPU**。

```python
import asyncio

async def fetch_data():
    print("开始获取数据...")
    await asyncio.sleep(2)  # 模拟网络请求，等待2秒
    # ↑ await 告诉 Python："这里要等2秒，先去处理别的协程"
    print("数据获取完成！")
    return {"data": "hello"}
```

### 2.3 await 的规则

1. `await` **只能在 `async def` 函数内**使用
2. `await` 后面**只能跟可等待对象**（协程、Task、Future）
3. 普通函数**不能 `await`**
4. `await` 不是 `sleep` —— 它是"让出控制权"

```python
# ✅ 正确
async def good():
    await asyncio.sleep(1)

# ❌ 错误：普通函数里不能用 await
def bad():
    await asyncio.sleep(1)  # SyntaxError!
```

### 2.4 运行协程

协程不能直接调用，需要通过事件循环运行：

```python
import asyncio

async def main():
    print("Hello")
    await asyncio.sleep(1)
    print("World")

# 运行协程的标准方式
asyncio.run(main())
```

### 2.5 执行流程图

```
asyncio.run(main())
        │
        ▼
  事件循环启动
        │
        ├─ 执行 main()
        │   ├─ print("Hello")
        │   ├─ await asyncio.sleep(1)
        │   │       │
        │   │       └─ 让出控制权，1秒后回来
        │   │          （如果有其他协程，这时会去执行它们）
        │   │
        │   └─ print("World")  ← 1秒后继续
        │
        └─ 事件循环结束
```

## 三、并发执行多个协程

### 3.1 `asyncio.gather()` —— 同时执行多个任务

这是异步最强大的地方：**同时发起多个等待操作**。

```python
import asyncio

async def call_api(name, seconds):
    print(f"  {name}: 开始请求...")
    await asyncio.sleep(seconds)
    print(f"  {name}: 请求完成！")
    return f"{name}的结果"

async def main():
    # 同时发起3个请求
    results = await asyncio.gather(
        call_api("Claude API", 2),
        call_api("向量数据库", 1),
        call_api("DeepSeek API", 1.5),
    )
    print(f"  所有结果: {results}")

asyncio.run(main())
```

**同步执行**: 2 + 1 + 1.5 = 4.5 秒
**异步执行**: max(2, 1, 1.5) = 2 秒（取最慢的那个）

### 3.2 `asyncio.create_task()` —— 创建后台任务

```python
async def main():
    # 创建任务（立即开始执行，不等待）
    task1 = asyncio.create_task(call_api("任务1", 2))
    task2 = asyncio.create_task(call_api("任务2", 1))

    # 做一些其他事情...
    print("任务已创建，我先干别的")

    # 需要结果时再 await
    result1 = await task1
    result2 = await task2
```

### 3.3 gather vs create_task

| | `asyncio.gather()` | `asyncio.create_task()` |
|--|---------------------|------------------------|
| 用法 | 一次性等待所有结果 | 先创建任务，后面再等结果 |
| 返回 | 所有结果的列表 | 单个 Task 对象 |
| 场景 | 需要同时完成多件事 | 需要更灵活的控制 |

## 四、异步实际应用场景

### 4.1 异步 HTTP 请求（AI 项目核心）

```python
import httpx  # 异步 HTTP 客户端（比 requests 好，支持异步）
import asyncio

async def call_llm(prompt):
    async with httpx.AsyncClient() as client:
        response = await client.post(
            "http://localhost:11434/api/generate",
            json={"model": "qwen2.5:7b", "prompt": prompt}
        )
        return response.json()
```

注意：`requests` 库不支持异步，要用 `httpx` 或 `aiohttp`。

### 4.2 异步文件操作

```python
import aiofiles  # 异步文件读写库

async def read_document(path):
    async with aiofiles.open(path, 'r', encoding='utf-8') as f:
        content = await f.read()
    return content
```

### 4.3 同时处理多个文档（RAG 项目会用到）

```python
async def process_documents(file_paths):
    """同时处理多个文档，比一个一个处理快得多"""
    tasks = [read_and_embed(path) for path in file_paths]
    results = await asyncio.gather(*tasks)
    return results
```

## 五、异步的常见陷阱

### 5.1 不能在异步函数里调用同步的阻塞操作

```python
import time

# ❌ 错误：time.sleep 会阻塞整个事件循环！
async def bad_example():
    time.sleep(3)  # 这会卡住所有其他协程

# ✅ 正确：用 asyncio.sleep
async def good_example():
    await asyncio.sleep(3)  # 等待时让出控制权
```

### 5.2 如果必须用同步代码怎么办？

```python
import asyncio
import time

def sync_heavy_work():
    """模拟一个没有异步版本的同步操作"""
    time.sleep(2)
    return "完成"

async def main():
    loop = asyncio.get_event_loop()
    # run_in_executor 在线程池中运行同步代码，不会阻塞事件循环
    result = await loop.run_in_executor(None, sync_heavy_work)
    print(result)
```

### 5.3 忘记 await

```python
async def fetch():
    return "data"

async def main():
    result = fetch()      # ❌ 忘了 await！result 是协程对象，不是 "data"
    result = await fetch() # ✅ result 是 "data"
```

## 六、FastAPI 中的异步

### 6.1 同步路由 vs 异步路由

```python
from fastapi import FastAPI

app = FastAPI()

# 同步路由 —— FastAPI 自动放到线程池中运行
@app.get("/sync")
def sync_endpoint():
    # 这里可以用普通的同步代码
    import time
    time.sleep(1)
    return {"message": "sync"}

# 异步路由 —— 直接在事件循环中运行
@app.get("/async")
async def async_endpoint():
    # 这里必须用异步代码
    import asyncio
    await asyncio.sleep(1)
    return {"message": "async"}
```

### 6.2 什么时候用 async def？什么时候用 def？

```
你的路由函数里有 await 调用吗？
        │
        ├─ 有 → 用 async def
        │       例：调用异步数据库、异步 HTTP 请求
        │
        └─ 没有 → 用 def
                例：纯 CPU 计算、调用同步库（requests）
```

FastAPI 的聪明之处：
- `async def` 路由直接在主事件循环运行
- `def` 路由自动放到线程池运行（所以同步代码不会阻塞其他请求）

### 6.3 FastAPI 异步实战模式

```python
from fastapi import FastAPI
import httpx

app = FastAPI()

# AI 问答接口的典型异步模式
@app.post("/chat")
async def chat(question: str):
    # 1. 异步查询向量数据库
    docs = await search_vector_db(question)

    # 2. 异步调用大模型
    answer = await call_llm(question, context=docs)

    # 3. 异步保存对话记录
    await save_chat_history(question, answer)

    return {"answer": answer}
```

## 七、asyncio 常用 API 速查

| API | 作用 | 使用场景 |
|-----|------|---------|
| `asyncio.run(coro)` | 运行协程（程序入口） | `asyncio.run(main())` |
| `await asyncio.sleep(n)` | 异步等待 n 秒 | 模拟延迟、限速 |
| `await asyncio.gather(*coros)` | 并发执行多个协程 | 同时调用多个 API |
| `asyncio.create_task(coro)` | 创建后台任务 | 非阻塞地启动协程 |
| `asyncio.wait_for(coro, timeout)` | 带超时的等待 | API 调用超时控制 |
| `asyncio.Semaphore(n)` | 限制并发数 | 控制同时发起的请求数 |
| `loop.run_in_executor()` | 在线程池中运行同步代码 | 没有异步版本的库 |

## 八、面试常问

1. **async/await 是什么？** → `async` 定义协程函数，`await` 在等待时让出控制权给其他协程
2. **异步和多线程有什么区别？** → 异步是单线程+事件循环（协作式），多线程是多线程+锁（抢占式）。异步更轻量，没有锁的问题
3. **FastAPI 为什么用异步？** → Web 服务是 IO 密集型（等网络、等数据库），异步能在等待时处理其他请求，大幅提升并发能力
4. **什么场景不适合异步？** → CPU 密集型计算（如训练模型、大量数学运算），应该用多进程
5. **`asyncio.gather` 和 `create_task` 的区别？** → gather 一次性等待所有结果返回列表，create_task 创建后台任务可以后续单独 await
