# Day 14：文档解析与分割

> RAG 的第一步不是检索，而是把各种格式的文档变成干净的文本块。
> 垃圾进，垃圾出 —— 文档解析质量直接决定 RAG 效果。

---

## 一、为什么文档解析很重要？

### 1.1 RAG 管线中的位置

```
文档解析是 RAG 的"入口"，一切从这里开始：

  PDF/Word/MD/TXT
        |
        v
  [文档解析] ← 今天学这个
        |
        v
  纯净文本
        |
        v
  [文本分割] ← 今天也学这个
        |
        v
  文本块(chunks)
        |
        v
  [Embedding] → 向量数据库 → 检索 → LLM 回答
```

### 1.2 解析质量 vs RAG 效果

| 解析质量 | 结果 |
|----------|------|
| 好的解析 | 文本干净、结构清晰、表格保留 → 检索精准 → 回答正确 |
| 差的解析 | 乱码、重复、丢失格式 → 检索到垃圾 → 回答离谱 |

**真实案例**：一个 PDF 里的表格，如果解析成一堆零散文字，检索时根本找不到完整的一行数据。

## 二、各格式文档解析

### 2.1 纯文本 / Markdown

最简单的情况，直接读取即可：

```python
# 纯文本
with open("doc.txt", "r", encoding="utf-8") as f:
    text = f.read()

# Markdown - 同样直接读取，保留结构用于后续按标题分割
with open("doc.md", "r", encoding="utf-8") as f:
    md_text = f.read()
```

Markdown 的优势：有 `#`、`##` 等结构标记，可以利用标题做智能分割。

### 2.2 PDF 解析

PDF 是 RAG 最常见也最头疼的格式。三个主流库各有特长：

| 库 | 安装 | 优点 | 缺点 |
|----|------|------|------|
| **PyPDF2** | `pip install PyPDF2` | 简单、轻量 | 表格解析差、复杂排版丢失 |
| **pdfplumber** | `pip install pdfplumber` | **表格解析好** | 速度稍慢 |
| **PyMuPDF(fitz)** | `pip install pymupdf` | 速度快、功能全 | 包较大 |

```python
# === PyPDF2：基础文本提取 ===
from PyPDF2 import PdfReader

reader = PdfReader("document.pdf")
for page in reader.pages:
    text = page.extract_text()
    print(text)

# === pdfplumber：擅长表格 ===
import pdfplumber

with pdfplumber.open("document.pdf") as pdf:
    for page in pdf.pages:
        # 提取文本
        text = page.extract_text()
        # 提取表格（返回二维列表）
        tables = page.extract_tables()
        for table in tables:
            for row in table:
                print(" | ".join(str(cell) for cell in row))

# === PyMuPDF：速度最快 ===
import fitz  # pymupdf 导入名是 fitz

doc = fitz.open("document.pdf")
for page in doc:
    text = page.get_text()
    print(text)
```

**面试回答**：我在项目中根据文档类型选择解析库 —— 普通 PDF 用 PyMuPDF（速度快），含表格的 PDF 用 pdfplumber（表格准确）。

### 2.3 Word/Docx 解析

```python
# === python-docx：结构化解析 ===
from docx import Document

doc = Document("report.docx")

# 按段落读取（保留结构）
for para in doc.paragraphs:
    print(f"[{para.style.name}] {para.text}")
    # style.name 可以是 'Heading 1', 'Normal' 等
    # 利用这个信息做智能分割

# 读取表格
for table in doc.tables:
    for row in table.rows:
        row_text = [cell.text for cell in row.cells]
        print(" | ".join(row_text))
```

### 2.4 LangChain 文档加载器

LangChain 封装了各种格式的加载器，统一接口：

```python
from langchain_community.document_loaders import (
    TextLoader,           # .txt
    UnstructuredMarkdownLoader,  # .md
    PyPDFLoader,          # .pdf
    Docx2txtLoader,       # .docx
    DirectoryLoader,      # 整个目录
)

# 加载单个文件
loader = TextLoader("doc.txt", encoding="utf-8")
docs = loader.load()  # 返回 [Document(page_content=..., metadata=...)]

# 加载整个目录下所有 .md 文件
loader = DirectoryLoader("./docs/", glob="**/*.md", loader_cls=TextLoader)
docs = loader.load()

# 每个 Document 对象有：
# - page_content: 文本内容
# - metadata: {"source": "doc.txt", "page": 0, ...}
```

## 三、文本分割策略（重点）

### 3.1 为什么要分割？

```
问题：一篇 5000 字的文档，直接存入向量库会怎样？

1. Embedding 质量差 —— 太长的文本，向量无法捕捉具体信息
2. 检索不精准 —— 用户问具体问题，匹配到整篇文档，信息密度低
3. 超出 LLM 上下文 —— 检索到 5 篇 5000 字文档 = 25000 字，可能超限

所以：必须把长文档切成短的"文本块"（chunk）
```

### 3.2 分割策略对比

```
策略1: 固定大小分割（最简单）
+----+----+----+----+
|500字|500字|500字|500字|  ← 机械切割，可能切断句子
+----+----+----+----+

策略2: 按段落/句子分割
+--------+------+-----------+---+
|  段落1  | 段落2 |   段落3    |段4|  ← 保持语义完整
+--------+------+-----------+---+

策略3: 递归分割（LangChain 默认，推荐）
先按 \n\n 分 → 太长则按 \n 分 → 还太长按句号分 → 再长按空格分
+--------+------+----+----+---+
| 完整段落 | 段落2 |句子1|句子2|句3|  ← 尽量保持大结构，必要时细分
+--------+------+----+----+---+

策略4: 语义分割（高级）
根据文本语义变化点来切 → 效果最好但需要额外计算 Embedding
```

### 3.3 RecursiveCharacterTextSplitter（必须掌握）

这是 LangChain 中最常用的分割器，也是面试必问的：

```python
from langchain.text_splitter import RecursiveCharacterTextSplitter

splitter = RecursiveCharacterTextSplitter(
    chunk_size=500,        # 每个 chunk 最大 500 字符
    chunk_overlap=100,     # 相邻 chunk 重叠 100 字符
    separators=[           # 分割优先级（从上到下尝试）
        "\n\n",            # 1. 先按空行分（段落）
        "\n",              # 2. 再按换行分
        "。",              # 3. 再按句号分（中文）
        ".",               # 4. 英文句号
        " ",               # 5. 空格
        "",                # 6. 逐字符（最后手段）
    ],
    length_function=len,   # 用什么计算长度
)

chunks = splitter.split_text(long_text)
```

**工作原理**：

```
输入：一段 2000 字的文本，chunk_size=500

Step 1: 尝试用 "\n\n" 分割
  → 得到 3 个段落：800字、600字、600字
  → 都超过 500，继续分

Step 2: 对每个超长段落，尝试用 "\n" 分割
  → 800字段落 → 300字 + 500字
  → 500字刚好，300字不需要再分

Step 3: 如果还有超长的，用句号分割...

最终：得到若干个 <= 500 字符的 chunk
每个 chunk 和前一个有 100 字符的重叠
```

### 3.4 chunk_size 和 chunk_overlap 怎么选？

| 参数 | 推荐范围 | 选大了 | 选小了 |
|------|----------|--------|--------|
| **chunk_size** | 500-1000 字符 | 信息密度低，检索不精准 | 上下文断裂，语义不完整 |
| **chunk_overlap** | 50-200 字符 | 冗余多，存储浪费 | 可能丢失跨块信息 |

**经验法则**：

```
中文文档：chunk_size=500, overlap=100
英文文档：chunk_size=1000, overlap=200
代码文档：chunk_size=1500, overlap=200（代码段通常更长）
Q&A 对：不分割，每个 Q&A 作为一个 chunk
```

**调参方法**：没有绝对最优值，需要根据实际检索效果调整。先用默认值，再根据测试结果微调。

## 四、处理特殊内容

### 4.1 表格处理

表格直接分割会丢失行列关系：

```
原始表格：
  姓名 | 年龄 | 城市
  张三 | 25   | 北京
  李四 | 30   | 上海

错误做法：把表格当普通文本分割
  → "张三 25 北京 李四 30 上海"  （丢失了结构）

正确做法：
  方法1: 转成文字描述
  → "张三，年龄25，城市北京。李四，年龄30，城市上海。"

  方法2: 保留 Markdown 表格格式作为一个完整 chunk
  → "| 姓名 | 年龄 | 城市 |\n|------|------|------|\n| 张三 | 25 | 北京 |..."
```

### 4.2 代码块处理

```python
# 代码块应该作为完整的 chunk，不要从中间切开
# LangChain 提供了代码专用分割器：
from langchain.text_splitter import Language, RecursiveCharacterTextSplitter

python_splitter = RecursiveCharacterTextSplitter.from_language(
    language=Language.PYTHON,
    chunk_size=1000,
    chunk_overlap=100,
)
```

### 4.3 利用标题作为元数据

```python
# 分割时保留标题信息，检索时更有上下文
from langchain.text_splitter import MarkdownHeaderTextSplitter

headers_to_split_on = [
    ("#", "h1"),
    ("##", "h2"),
    ("###", "h3"),
]

splitter = MarkdownHeaderTextSplitter(headers_to_split_on=headers_to_split_on)
chunks = splitter.split_text(md_text)

# 每个 chunk 自带 metadata：
# Document(page_content="...", metadata={"h1": "FastAPI", "h2": "安装"})
```

## 五、完整管线：文件 → 解析 → 分割 → 带元数据的 Chunks

```python
import os
from langchain.text_splitter import RecursiveCharacterTextSplitter

def process_documents(directory: str) -> list[dict]:
    """
    完整的文档处理管线
    输入: 文档目录路径
    输出: 带元数据的 chunk 列表
    """
    splitter = RecursiveCharacterTextSplitter(
        chunk_size=500,
        chunk_overlap=100,
    )

    all_chunks = []
    for filename in os.listdir(directory):
        filepath = os.path.join(directory, filename)

        # Step 1: 根据格式解析
        if filename.endswith(".txt") or filename.endswith(".md"):
            with open(filepath, "r", encoding="utf-8") as f:
                text = f.read()
        elif filename.endswith(".pdf"):
            text = parse_pdf(filepath)    # 用前面的方法
        elif filename.endswith(".docx"):
            text = parse_docx(filepath)   # 用前面的方法
        else:
            continue

        # Step 2: 分割
        chunks = splitter.split_text(text)

        # Step 3: 添加元数据
        for i, chunk in enumerate(chunks):
            all_chunks.append({
                "content": chunk,
                "metadata": {
                    "source": filename,
                    "chunk_index": i,
                    "total_chunks": len(chunks),
                }
            })

    return all_chunks  # 下一步: Embedding → 存入向量库
```

## 六、面试常问

### Q1: RAG 中文档解析的挑战有哪些？

> 1. PDF 格式多样，扫描件需要 OCR，表格解析困难
> 2. 不同编码（UTF-8/GBK）需要正确处理
> 3. 特殊内容（公式、图片、表格）需要专门处理
> 4. 多语言混排文档需要统一处理

### Q2: chunk_size 怎么选？太大太小分别有什么问题？

> chunk_size 通常 500-1000 字符。太大导致 Embedding 信息密度低、检索不精准；
> 太小导致上下文断裂、语义不完整。需要根据实际检索效果调参。

### Q3: chunk_overlap 有什么用？

> 防止重要信息被切断。比如一个关键句子正好在切割点上，有 overlap 就能在相邻的两个 chunk 中都保留这个句子，确保检索时不丢信息。

### Q4: RecursiveCharacterTextSplitter 为什么叫"递归"？

> 因为它有多级分隔符（段落→换行→句号→空格），先尝试用大粒度分割，如果某段还是超过 chunk_size，就递归地用更小粒度的分隔符继续分割。

### Q5: 你在项目中怎么处理 PDF 表格？

> 用 pdfplumber 提取表格结构，转换成 Markdown 格式或文字描述后再分割。保证表格的行列关系不丢失，这样检索时能找到完整的数据行。
