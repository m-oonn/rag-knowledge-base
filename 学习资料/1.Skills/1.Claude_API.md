## 一、大模型 API 是什么？

### 1.1 和 ChatGPT 网页版的区别

| | 网页版（ChatGPT/Claude） | API 调用 |
|--|-------------------------|---------|
| 使用方式 | 浏览器聊天 | 代码发 HTTP 请求 |
| 适合谁 | 普通用户 | 开发者 |
| 能力 | 只能聊天 | 嵌入到你的应用里 |
| 定制性 | 几乎没有 | 完全可控（系统提示词、温度、格式等）|

你做的 RAG 项目，本质就是：**用代码调用大模型 API，把检索到的文档作为上下文一起发给它**。

### 1.2 API 调用流程

```
你的代码 → 构造请求（messages + 参数）→ 发送到 Claude 服务器 → 模型生成回答 → 返回给你的代码
```

## 三、核心概念

### 3.1 Messages 格式

Claude API 的核心是 **messages 列表**，每条消息有 role 和 content：

```python
messages = [
    {"role": "user", "content": "你好，请介绍一下Python"},
    # role 只有两种：user（用户说的）和 assistant（AI说的）
]
```

多轮对话就是把历史消息都带上：
```python
messages = [
    {"role": "user", "content": "什么是Python？"},
    {"role": "assistant", "content": "Python是一种高级编程语言..."},
    {"role": "user", "content": "它能做AI开发吗？"},
    # 模型看到完整对话历史，才能理解"它"指的是Python
]
```

### 3.2 System Prompt（系统提示词）

系统提示词是给模型的"人设"指令，用户看不到：

```python
response = client.messages.create(
    model="claude-sonnet-4-20250514",
    max_tokens=1024,
    system="你是一个Python编程助手，回答简洁，代码示例用中文注释。",
    messages=[{"role": "user", "content": "怎么读文件？"}],
)
```

### 3.3 关键参数

| 参数 | 含义 | 建议值 |
|------|------|--------|
| `model` | 模型版本 | `claude-sonnet-4-20250514`（性价比最高）|
| `max_tokens` | 最大输出长度 | 1024-4096 |
| `temperature` | 创造性（0=确定性，1=创造性）| 0-0.3（代码/分析）；0.7-1（创意/对话）|
| `system` | 系统提示词 | 根据场景定制 |

### 3.4 Token 是什么？

Token ≈ 一个汉字或半个英文单词。API 按 token 收费：
- 输入 token：你发给模型的（messages + system）
- 输出 token：模型返回的回答
- Claude Sonnet：输入 $3/百万token，输出 $15/百万token

**省钱技巧**：system 提示词尽量简洁，不需要时减少历史消息数量。

## 四、流式输出

### 4.1 为什么需要流式？

普通模式：等模型生成完所有内容，一次性返回（用户等 5 秒看到完整回答）
流式模式：模型生成一个 token 就返回一个（用户看到逐字出现，体验好很多）

ChatGPT / Claude 网页版就是流式输出。

### 4.2 流式原理

```
普通模式:
  请求 → [等待5秒] → "Python是一种高级编程语言，由Guido创造..."

流式模式:
  请求 → "Python" → "是" → "一种" → "高级" → "编程" → ... → [完成]
         50ms      50ms    50ms     50ms    50ms
```

### 4.3 SSE（Server-Sent Events）

流式输出用的是 SSE 协议：
- 服务器不断向客户端推送小块数据
- 客户端逐块接收并显示
- 你后面 RAG 项目的流式输出也是这个原理

## 五、错误处理

常见错误和解决方案：

| 错误 | 原因 | 解决 |
|------|------|------|
| `401 Unauthorized` | API Key 无效 | 检查 Key 是否正确 |
| `429 Too Many Requests` | 请求太频繁 | 加延迟或用重试装饰器 |
| `500 Server Error` | 服务端问题 | 等一会儿重试 |
| `context_length_exceeded` | 输入太长 | 减少历史消息或文档长度 |

## 六、和 FastAPI 结合

这就是你后面项目的核心模式：

```python
from fastapi import FastAPI
from anthropic import Anthropic

app = FastAPI()
client = Anthropic()

@app.post("/chat")
async def chat(question: str):
    response = client.messages.create(
        model="claude-sonnet-4-20250514",
        max_tokens=1024,
        messages=[{"role": "user", "content": question}],
    )
    return {"answer": response.content[0].text}
```

## 七、面试相关

1. **Token 是什么？怎么计费？** → Token ≈ 一个汉字，按输入+输出 token 数计费
2. **流式输出怎么实现？** → SSE 协议，模型生成一个 token 就推送一个
3. **system prompt 和 user message 的区别？** → system 是全局指令（人设），user 是具体问题
4. **怎么实现多轮对话？** → 把历史 messages 列表全部发给 API
5. **怎么控制输出格式？** → system prompt 中指定 + temperature 调低
