## 一、Prompt 工程是什么？

### 1.1 一句话理解

Prompt 工程 = **通过精心设计输入文本，让大模型给出你想要的输出**。

不是"随便问一句"，而是用结构化的方式告诉模型：
- 你是谁（角色）
- 要做什么（任务）
- 怎么做（规则）
- 输出什么格式（格式）

### 1.2 为什么重要？

```
差的 Prompt: "帮我分析数据"
→ 模型不知道什么数据、怎么分析、输出什么格式，回答又长又空

好的 Prompt: "你是数据分析师。分析以下 CSV 数据的销售趋势，
             用中文输出 JSON 格式，包含 trend（上升/下降/平稳）
             和 summary（一句话总结）字段。数据：..."
→ 模型精准输出你要的 JSON
```

### 1.3 在你项目中的应用

| 项目 | Prompt 用在哪 |
|------|-------------|
| RAG 知识库 | 让模型根据检索到的文档回答问题，要求引用来源 |
| 数据分析 Agent | 让模型理解用户需求 → 生成 pandas 代码 → 分析结果写报告 |
| 面试 | "你了解 Prompt Engineering 吗？" 必问题 |

## 二、System Prompt（系统提示词）

### 2.1 作用

System Prompt 是给模型的**全局指令**，定义模型的角色、能力、限制。用户看不到。

### 2.2 好的 System Prompt 模板

```
你是{角色}。

## 任务
{要做什么}

## 规则
- {规则1}
- {规则2}
- {规则3}

## 输出格式
{JSON/Markdown/纯文本...}
```

### 2.3 示例对比

```
❌ 差: "你是助手"

✅ 好: "你是一个Python编程助手，专门帮助初学者理解代码。
       规则：
       1. 用中文回答
       2. 代码示例加中文注释
       3. 每次回答不超过200字
       4. 遇到不确定的问题，说明你不确定而不是编造答案"
```

## 三、核心技巧

### 3.1 少样本学习（Few-Shot Learning）

**给模型看几个例子，它就知道你要什么格式**。这是最实用的技巧。

```
请将用户问题分类。

示例1：
问题：Python怎么读文件？
分类：技术问题

示例2：
问题：今天天气怎么样？
分类：闲聊

示例3：
问题：你能帮我写简历吗？
分类：请求帮助

现在请分类：
问题：FastAPI的依赖注入怎么用？
分类：
```

模型看到 3 个例子后，自然知道要输出"技术问题"。

**适用场景**：
- 分类任务
- 格式化输出
- 风格统一

### 3.2 思维链（Chain of Thought, CoT）

**让模型"想一步说一步"，而不是直接给答案**。

```
❌ 直接问: "小明有5个苹果，给了小红2个，又买了3个，还剩几个？"
→ 模型可能直接说"6个"（有时会算错）

✅ 加思维链: "请一步一步思考：
小明有5个苹果，给了小红2个，又买了3个，还剩几个？
请先列出每一步的计算过程，再给出最终答案。"
→ 模型会写：
  1. 初始：5个
  2. 给小红2个：5-2=3个
  3. 又买3个：3+3=6个
  答案：6个
```

**适用场景**：
- 复杂推理
- 数学计算
- 代码调试分析
- Agent 的规划步骤

### 3.3 角色扮演

**给模型一个具体角色，它的回答质量会明显提高**。

```
你是一位有10年经验的Python后端工程师，擅长FastAPI和微服务架构。
你正在帮助一个大三学生做毕业项目（RAG知识库系统）。
请用通俗易懂的语言解释技术概念，必要时给出代码示例。
```

### 3.4 结构化输出（JSON/XML）

**RAG 和 Agent 项目的核心需求：让模型输出可解析的结构化数据。**

```
分析以下用户问题，输出 JSON 格式：

用户问题："帮我分析最近3个月的销售数据，画一个趋势图"

请输出以下 JSON（不要输出其他内容）：
{
  "intent": "数据分析/问答/闲聊",
  "needs_chart": true/false,
  "time_range": "提到的时间范围",
  "data_type": "涉及的数据类型"
}
```

**关键技巧**：
- 明确说"输出 JSON 格式"
- 给出 JSON 模板
- 说"不要输出其他内容"
- temperature 设低（0-0.3）

### 3.5 分隔符

**用分隔符把不同部分隔开，防止注入和混淆。**

```
根据以下文档回答用户问题。

---文档内容---
{document_text}
---文档结束---

用户问题：{user_question}

请根据文档内容回答，如果文档中没有相关信息，请说"文档中未找到相关信息"。
```

`---文档内容---` 和 `---文档结束---` 就是分隔符，让模型清楚区分文档和指令。

### 3.6 限制与兜底

**告诉模型"不要做什么"和"不确定时怎么办"。**

```
规则：
- 只根据提供的文档内容回答，不要使用你自己的知识
- 如果文档中没有相关信息，回答"抱歉，知识库中未找到相关信息"
- 不要编造不存在的内容
- 如果问题涉及多个方面，分点回答
```

这在 RAG 项目中**极其重要** —— 防止模型"编造"不在文档里的内容。

## 四、RAG 项目中的 Prompt 模板

这是你项目一的核心 Prompt，提前预览：

```python
RAG_PROMPT = """你是一个知识库问答助手。

## 任务
根据提供的参考文档，回答用户的问题。

## 参考文档
{context}

## 规则
1. 只根据参考文档的内容回答，不要使用你自己的知识
2. 回答后标注信息来源，格式：[来源：文档名称]
3. 如果参考文档中没有相关信息，回答"知识库中未找到相关信息"
4. 用中文回答，语言简洁清晰
5. 如果问题涉及多个方面，分点作答

## 用户问题
{question}
"""
```

```python
AGENT_PROMPT = """你是一个数据分析师 Agent。

## 任务
根据用户的自然语言描述，分析提供的数据。

## 当前数据
文件：{file_name}
列名：{columns}
前5行：{preview}

## 用户需求
{user_request}
"""
```

## 七、面试常问

1. **什么是 Prompt Engineering？** → 通过设计输入文本来控制 LLM 输出质量和格式的技术
2. **Few-Shot 和 Zero-Shot 的区别？** → Few-Shot 给例子，Zero-Shot 不给例子直接问。Few-Shot 效果更稳定
3. **Chain of Thought 是什么？** → 让模型逐步推理而不是直接给答案，提高复杂任务的准确率
4. **怎么让模型输出稳定的 JSON？** → System Prompt 指定格式 + 给 JSON 模板 + temperature 设低 + Few-Shot 示例
5. **RAG 中 Prompt 怎么设计？** → 将检索到的文档作为上下文注入 Prompt，要求模型只根据文档回答并标注来源
6. **怎么防止模型编造内容？** → 明确规则"只根据文档回答"+"不确定就说不知道"+检索结果为空时有兜底回答
