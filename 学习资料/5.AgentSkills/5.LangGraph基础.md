## 一、什么是 LangGraph？

### 1.1 一句话理解

LangGraph = **用"图"（Graph）来编排 AI 工作流**。

- **节点（Node）**：每个节点是一个处理步骤（函数）
- **边（Edge）**：节点之间的连接，决定执行顺序
- **状态（State）**：在节点之间流转的共享数据

```
传统编程：  函数A() → 函数B() → 函数C()   （线性调用）
LangGraph：
                    ┌── 节点B ──┐
  START → 节点A ──┤            ├── 节点D → END
                    └── 节点C ──┘
  （可以分支、循环、条件跳转）
```

### 1.2 为什么不用普通 LangChain？

| 特性 | LangChain (Chain/AgentExecutor) | LangGraph |
|------|-------------------------------|-----------|
| 控制流 | 线性链式，难以自定义 | 图结构，任意控制流 |
| 状态管理 | 隐式，不透明 | 显式 TypedDict，完全可控 |
| 循环支持 | 有限（Agent 循环是内置的） | 原生支持任意循环 |
| 条件分支 | 不灵活 | 条件边，任意路由 |
| 可调试性 | 黑盒，难以追踪 | 每个节点的输入输出都可观察 |
| 人工介入 | 很难实现 | 内置 interrupt 支持 |
| 适合场景 | 简单的线性任务 | **复杂 Agent、多步骤工作流** |

**结论**：做简单的"问→答"用 LangChain 够了，做 Agent 用 LangGraph。

## 二、核心概念

### 2.1 StateGraph —— 图的容器

```python
from langgraph.graph import StateGraph

# 创建一个图，需要指定状态类型
graph = StateGraph(MyState)
```

### 2.2 State —— 状态定义

状态是一个 `TypedDict`，定义了在图中流转的所有数据：

```python
from typing import TypedDict, Annotated
from langgraph.graph.message import add_messages

class MyState(TypedDict):
    messages: Annotated[list, add_messages]  # 消息列表（自动追加）
    intent: str                              # 用户意图
    result: str                              # 处理结果
```

**关键点**：
- `Annotated[list, add_messages]`：使用 reducer 函数，新消息会追加而不是覆盖
- 普通字段（如 `intent: str`）：每次赋值直接覆盖

### 2.3 Node —— 节点（处理函数）

每个节点是一个**普通 Python 函数**：

```python
def process_node(state: MyState) -> dict:
    """
    节点函数签名：
    - 输入：完整的 state
    - 输出：partial state update（只返回要更新的字段）
    """
    # 读取状态
    messages = state["messages"]
    # 处理逻辑...
    # 返回要更新的字段（不需要返回全部字段）
    return {"intent": "greeting", "result": "你好！"}
```

**节点函数的规则**：
1. 接收完整 state 作为参数
2. 返回一个 dict，只包含要更新的字段
3. 未返回的字段保持不变

### 2.4 Edge —— 边（连接）

```python
# 普通边：A 执行完必定到 B
graph.add_edge("node_a", "node_b")

# 条件边：A 执行完根据条件去 B 或 C
graph.add_conditional_edges(
    "node_a",           # 源节点
    routing_function,   # 路由函数：接收 state，返回下一个节点名
    {                   # 路由映射
        "go_b": "node_b",
        "go_c": "node_c",
    }
)
```

### 2.5 START 和 END

```python
from langgraph.graph import START, END

# START：图的入口，第一个被执行的节点从 START 连过去
graph.add_edge(START, "first_node")

# END：图的出口，执行到这里图就结束了
graph.add_edge("last_node", END)
```

### 2.6 编译和执行

```python
# 编译图（检查结构、优化执行路径）
app = graph.compile()

# 执行图
result = app.invoke({"messages": [("user", "你好")]})
```

## 三、完整工作流程

### 3.1 构建一个图的五步法

```
Step 1: 定义 State（TypedDict）
         ↓
Step 2: 创建 StateGraph(State)
         ↓
Step 3: 添加节点 graph.add_node("name", function)
         ↓
Step 4: 添加边   graph.add_edge("A", "B")
                  graph.add_conditional_edges(...)
         ↓
Step 5: 编译     app = graph.compile()
         ↓
执行:              result = app.invoke(initial_state)
```

### 3.2 最简示例

```python
from typing import TypedDict
from langgraph.graph import StateGraph, START, END

# Step 1: 定义状态
class State(TypedDict):
    text: str
    result: str

# Step 2 & 3: 创建图 + 添加节点
def process(state: State) -> dict:
    return {"result": f"处理完成: {state['text']}"}

graph = StateGraph(State)
graph.add_node("process", process)

# Step 4: 添加边
graph.add_edge(START, "process")
graph.add_edge("process", END)

# Step 5: 编译执行
app = graph.compile()
result = app.invoke({"text": "Hello", "result": ""})
print(result["result"])  # 处理完成: Hello
```

## 四、条件路由详解

### 4.1 路由函数

```python
def route_by_intent(state: State) -> str:
    """路由函数：根据 state 决定下一步去哪"""
    intent = state.get("intent", "unknown")
    if intent == "greeting":
        return "go_greet"
    elif intent == "question":
        return "go_answer"
    else:
        return "go_default"
```

### 4.2 条件边连接

```python
graph.add_conditional_edges(
    "classify_node",       # 从哪个节点出发
    route_by_intent,       # 路由函数
    {
        "go_greet":   "greet_node",    # 返回值 → 目标节点
        "go_answer":  "answer_node",
        "go_default": "default_node",
    }
)
```

### 4.3 流程图

```
                         ┌─ "greeting" ──→ greet_node ──┐
                         │                               │
START → classify_node ──┤── "question" ──→ answer_node ──┤──→ output_node → END
                         │                               │
                         └─ "default" ───→ default_node ─┘
```

## 五、State 中的 Reducer

### 5.1 什么是 Reducer？

普通字段赋值时**覆盖**旧值，但有时你需要**追加**（比如消息列表）。

```python
from typing import Annotated
from langgraph.graph.message import add_messages

class State(TypedDict):
    # 使用 add_messages reducer：新消息追加到列表末尾
    messages: Annotated[list, add_messages]
    # 普通字段：直接覆盖
    count: int
```

### 5.2 Reducer 的效果

```
初始 state:  {"messages": [msg1], "count": 0}

节点返回:    {"messages": [msg2], "count": 1}

结果 state:  {"messages": [msg1, msg2], "count": 1}
                          ↑ 追加了         ↑ 覆盖了
```

## 七、常见模式

### 7.1 线性管道

```
START → A → B → C → END
```

适合：数据预处理 → 模型调用 → 后处理

### 7.2 条件分支

```
         ┌── B ──┐
START → A┤       ├→ D → END
         └── C ──┘
```

适合：意图分类后走不同逻辑

### 7.3 循环（Agent 模式）

```
START → LLM_Node ──→ should_continue? ──→ Tool_Node ──┐
                           │                            │
                           ↓                            │
                          END            ←──────────────┘
```

适合：ReAct Agent（Day 36 详细学）

## 八、面试常问

1. **LangGraph 是什么？** --> 基于图结构的 AI 工作流编排框架，支持有状态、多步骤、可循环的流程控制
2. **LangGraph 和 LangChain 的区别？** --> LangChain 是线性链式调用，LangGraph 是图结构，支持条件分支和循环，状态管理更显式可控
3. **State 在 LangGraph 中怎么工作？** --> 用 TypedDict 定义状态结构，节点函数接收完整 state、返回 partial update，通过 Reducer 控制字段的更新方式
4. **什么是条件边？** --> 根据当前 state 的值，动态决定下一步执行哪个节点，通过路由函数实现
5. **LangGraph 怎么实现 Agent 循环？** --> 用条件边判断是否需要调用工具：需要则跳到 Tool 节点再回到 LLM 节点（形成循环），不需要则跳到 END
6. **节点函数的签名是什么？** --> 输入完整 state（TypedDict），输出 dict（只包含要更新的字段）
7. **为什么用 Annotated[list, add_messages]？** --> add_messages 是 reducer 函数，让新消息追加到列表而不是覆盖，适合对话场景
