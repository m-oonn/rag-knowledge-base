# Day 32：LangChain 工具系统

> 昨天你手写了 Function Calling 的完整循环，今天学习 LangChain 怎么把这个流程封装得更优雅。
> LangChain 的 Tool + Agent 体系是工业界最常用的 Agent 开发方式。

---

## 一、为什么用 LangChain 封装工具？

### 1.1 手写 vs 框架

```
手写 Function Calling（Day 31）:
  - 自己定义 JSON Schema
  - 自己解析 LLM 返回的 tool_calls
  - 自己执行函数
  - 自己把结果拼回 messages
  - 自己写循环
  → 50+ 行代码搞一个工具调用循环

LangChain Tool + Agent（Day 32）:
  - @tool 装饰器自动生成 Schema
  - AgentExecutor 自动管理调用循环
  - 内置错误处理和重试
  - 开箱即用的 ReAct 推理
  → 10 行代码搞定同样的事
```

### 1.2 什么时候用框架，什么时候手写？

| 场景 | 建议 |
|------|------|
| 学习原理 | 手写（Day 31 做的事） |
| 快速开发 Agent | 用 LangChain |
| 需要精细控制 | 手写或用 LangGraph |
| 生产环境 | LangChain + LangGraph |
| 面试回答 | 先说原理（手写），再说工具（LangChain） |

## 二、LangChain 的 Tool 抽象

### 2.1 三种创建工具的方式

```
方式一：@tool 装饰器        ← 最简单，90% 的场景用这个
方式二：StructuredTool     ← 从已有函数创建，不改原函数
方式三：继承 BaseTool      ← 最灵活，复杂工具用这个
```

### 2.2 方式一：@tool 装饰器

```python
from langchain_core.tools import tool

@tool
def get_weather(city: str) -> str:
    """获取指定城市的天气信息。当用户询问天气时调用此工具。"""
    # 函数体...
    return f"{city}今天晴天，25度"
```

**关键**：
- 函数的 docstring 自动变成工具的 description
- 参数的类型注解自动变成 JSON Schema
- 函数名自动变成工具名
- 所以 docstring 一定要写好！

### 2.3 方式二：StructuredTool.from_function

```python
from langchain_core.tools import StructuredTool

# 已有的普通函数（不想改它）
def my_search(query: str, top_k: int = 3) -> str:
    return f"搜索 {query} 的结果..."

# 包装成 LangChain Tool
search_tool = StructuredTool.from_function(
    func=my_search,
    name="search_knowledge",
    description="在知识库中搜索相关文档",
)
```

**适用场景**：已有的函数不方便加装饰器（比如第三方库的函数）。

### 2.4 方式三：继承 BaseTool

```python
from langchain_core.tools import BaseTool
from pydantic import BaseModel, Field

# 定义输入参数的 Schema
class CalculatorInput(BaseModel):
    expression: str = Field(description="数学表达式")

class CalculatorTool(BaseTool):
    name: str = "calculator"
    description: str = "计算数学表达式"
    args_schema: type = CalculatorInput

    def _run(self, expression: str) -> str:
        """同步执行"""
        return str(eval(expression))

    async def _arun(self, expression: str) -> str:
        """异步执行（可选）"""
        return self._run(expression)
```

**适用场景**：
- 需要异步执行（_arun）
- 需要自定义参数校验
- 需要复杂的初始化逻辑
- 需要访问外部资源（数据库连接等）

### 2.5 三种方式对比

| 特性 | @tool | StructuredTool | BaseTool |
|------|-------|---------------|----------|
| 代码量 | 最少 | 中等 | 最多 |
| 灵活性 | 低 | 中 | 高 |
| 异步支持 | 有限 | 有限 | 完整 |
| 参数校验 | 自动 | 自动 | 自定义 |
| 推荐场景 | 简单工具 | 包装已有函数 | 复杂工具 |
| 使用频率 | 90% | 8% | 2% |

## 三、工具的输入 Schema

### 3.1 自动推断

使用 @tool 时，LangChain 从函数签名自动推断 Schema：

```python
@tool
def search(query: str, max_results: int = 5) -> str:
    """搜索文档"""
    ...

# 自动生成的 Schema:
# {
#   "name": "search",
#   "description": "搜索文档",
#   "parameters": {
#     "type": "object",
#     "properties": {
#       "query": {"type": "string"},
#       "max_results": {"type": "integer", "default": 5}
#     },
#     "required": ["query"]
#   }
# }
```

### 3.2 用 Pydantic 精确控制

```python
from pydantic import BaseModel, Field

class SearchInput(BaseModel):
    """知识库搜索输入参数"""
    query: str = Field(description="搜索关键词")
    max_results: int = Field(default=5, ge=1, le=20, description="最大返回数量")
    category: str = Field(default="all", description="搜索类别: all/tech/news")

@tool(args_schema=SearchInput)
def search_knowledge(query: str, max_results: int = 5, category: str = "all") -> str:
    """在知识库中搜索相关文档。当用户需要查找资料时使用。"""
    ...
```

**Pydantic 的好处**：
- 每个参数有清晰的 description（LLM 能看到）
- 自动类型校验（ge=1, le=20 限制范围）
- 默认值处理

## 四、内置工具与 ToolKit

### 4.1 常用内置工具

LangChain 提供了一些开箱即用的工具：

| 工具 | 功能 | 安装 |
|------|------|------|
| PythonREPLTool | 执行 Python 代码 | langchain_experimental |
| WikipediaQueryRun | 搜索 Wikipedia | langchain_community[wikipedia] |
| DuckDuckGoSearchRun | 网络搜索 | langchain_community[duckduckgo] |
| ShellTool | 执行 Shell 命令 | langchain_community |
| RequestsGetTool | HTTP GET 请求 | langchain_community |

### 4.2 ToolKit 概念

ToolKit = 一组相关工具的集合。

```python
# 例如 SQLDatabaseToolkit 包含:
# - QuerySQLDatabasaTool（执行 SQL）
# - InfoSQLDatabaseTool（查看表结构）
# - ListSQLDatabaseTool（列出所有表）

from langchain_community.agent_toolkits import SQLDatabaseToolkit
toolkit = SQLDatabaseToolkit(db=db, llm=llm)
tools = toolkit.get_tools()  # 返回一组工具
```

**你的项目可能用到**：
- SQLDatabaseToolkit（数据分析 Agent 查询数据库）
- 自定义 RAGToolkit（包含检索、重排序等工具）

## 五、Agent + Tools：LangChain 的连接方式

### 5.1 什么是 Agent？

```
Agent = LLM + Tools + 推理策略

工作流程:
  用户问题
     ↓
  LLM 思考（应该用什么工具？）    ← 推理策略（ReAct）
     ↓
  调用工具 → 获取结果
     ↓
  LLM 继续思考（还需要什么？）
     ↓
  ...循环...
     ↓
  生成最终回答
```

### 5.2 create_react_agent

ReAct 是最经典的 Agent 推理策略（Day 34 详细学），LangChain 提供了开箱即用的实现：

```python
from langchain.agents import create_react_agent, AgentExecutor
from langchain_core.prompts import PromptTemplate

# ReAct Prompt 模板（LangChain 有默认的，也可以自定义）
prompt = PromptTemplate.from_template("""
Answer the following questions using the available tools.

Tools: {tools}
Tool Names: {tool_names}

Use this format:
Question: {input}
Thought: I need to think about what to do
Action: tool_name
Action Input: the input to the tool
Observation: the result
...repeat Thought/Action/Observation...
Thought: I now know the final answer
Final Answer: the final answer

{agent_scratchpad}
""")

# 创建 ReAct Agent
agent = create_react_agent(
    llm=llm,              # LLM 实例
    tools=tools,           # 工具列表
    prompt=prompt          # Prompt 模板
)

# AgentExecutor 管理执行循环
executor = AgentExecutor(
    agent=agent,
    tools=tools,
    verbose=True,          # 打印思考过程！
    max_iterations=5,      # 最大循环次数
    handle_parsing_errors=True  # 自动处理解析错误
)

# 运行
result = executor.invoke({"input": "北京天气怎么样？"})
```

### 5.3 AgentExecutor 做了什么？

```
AgentExecutor 自动做了 Day 31 你手写的所有事:

  ┌──────────────────────────────────┐
  │  AgentExecutor.invoke()          │
  │                                  │
  │  while iterations < max:         │
  │    action = agent.plan(input)    │  ← LLM 思考+决策
  │    if action == "Final Answer":  │
  │      return answer               │
  │    result = tool.run(action)     │  ← 执行工具
  │    observation = result           │
  │    feed back to agent             │  ← 结果反馈
  │  end while                       │
  └──────────────────────────────────┘
```

### 5.4 verbose=True 的输出示例

```
> Entering new AgentExecutor chain...

Thought: 用户想知道北京天气，我需要调用天气工具
Action: get_weather
Action Input: {"city": "北京"}
Observation: {"city": "北京", "temperature": 28, "condition": "晴天"}

Thought: 我已经获得了天气信息，可以回答用户了
Final Answer: 北京今天晴天，气温28度。

> Finished chain.
```

**verbose=True 在开发调试时非常有用**——能看到 LLM 的完整思考过程。

## 六、错误处理

### 6.1 工具执行错误

```python
@tool
def risky_tool(data: str) -> str:
    """可能出错的工具"""
    if not data:
        raise ValueError("数据不能为空")
    return f"处理结果: {data}"

# AgentExecutor 的 handle_parsing_errors=True 会:
# 1. 捕获工具抛出的异常
# 2. 把错误信息作为 Observation 反馈给 LLM
# 3. LLM 看到错误后可能会换一种方式重试
```

### 6.2 LLM 输出格式错误

```python
# 如果 LLM 没有按 ReAct 格式输出（比如直接说了答案），
# handle_parsing_errors=True 会把错误告诉 LLM 重新生成

executor = AgentExecutor(
    agent=agent,
    tools=tools,
    handle_parsing_errors=True,   # 捕获解析错误
    max_iterations=5,             # 防止无限重试
)
```

### 6.3 自定义错误处理

```python
# 可以传入自定义的错误处理函数
executor = AgentExecutor(
    agent=agent,
    tools=tools,
    handle_parsing_errors="输出格式不正确，请按 Thought/Action/Action Input 格式重试。",
)
```

## 七、工具设计最佳实践

### 7.1 工具粒度

```
太细: get_city_name(), get_temperature(), get_humidity()
  → LLM 需要调用3次才能获取完整天气

太粗: do_everything(task: str)
  → LLM 不知道什么时候该调用

刚好: get_weather(city: str) → 完整天气信息
  → 一次调用获取所有需要的信息
```

### 7.2 Description 原则

```
1. 说清楚工具做什么
2. 说清楚什么时候该用
3. 说清楚输入是什么格式
4. 如果有限制也要说

好的 description:
  "在知识库中搜索与查询最相关的文档片段。
   当用户提出需要查找资料或询问技术概念时使用。
   返回最相关的 top_k 个文档片段。
   不支持搜索图片或文件。"
```

### 7.3 返回值设计

```python
# 差: 返回 Python 对象
return {"temp": 28}  # LLM 看不懂

# 好: 返回清晰的文本描述
return "北京今天晴天，气温28度，湿度45%"  # LLM 能直接用

# 也好: 返回格式化的 JSON 字符串
return json.dumps({"city": "北京", "temp": 28}, ensure_ascii=False)
```

## 八、面试常问

1. **LangChain 中创建 Tool 的三种方式？** → @tool 装饰器（最简单）、StructuredTool.from_function（包装已有函数）、继承 BaseTool（最灵活）
2. **@tool 装饰器怎么知道参数类型？** → 从函数的类型注解（type hints）自动推断 JSON Schema
3. **AgentExecutor 的作用？** → 管理 Agent 的执行循环：LLM 思考 → 调用工具 → 反馈结果 → 继续思考，直到得出最终答案
4. **什么是 ReAct Agent？** → Reasoning + Acting 交替的推理策略，Agent 先思考（Thought），再行动（Action），观察结果（Observation），循环直到得出答案
5. **verbose=True 有什么用？** → 打印 Agent 的完整推理过程（Thought/Action/Observation），方便调试
6. **工具出错了 Agent 怎么办？** → handle_parsing_errors=True 会捕获错误，作为 Observation 反馈给 LLM，LLM 可以换一种方式重试
7. **怎么设计好的工具 description？** → 说清楚功能、使用场景、输入格式和限制，description 是 LLM 决定是否调用工具的唯一依据
