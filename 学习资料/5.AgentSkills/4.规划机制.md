# Day 34：规划机制（Planning & Reasoning）

> Agent 最强大的能力不是调用工具，而是**思考和规划**。
> 今天学习 Agent 怎么把复杂任务拆解成步骤、怎么边想边做、怎么自我纠错。

## 一、为什么 Agent 需要规划？

### 1.1 简单任务 vs 复杂任务

```
简单任务: "北京天气怎么样？"
  → 一步搞定: 调用 get_weather("北京")

复杂任务: "帮我分析这份销售数据，找出下滑最严重的地区，画个图"
  → 需要多步:
    1. 读取数据文件
    2. 按地区分组统计
    3. 计算下滑幅度
    4. 排序找出最严重的
    5. 画图
    6. 生成报告

没有规划能力的 Agent 会:
  - 漫无目的地调用工具
  - 忘记自己做到哪一步了
  - 在错误的方向上浪费大量尝试
```

### 1.2 人类是怎么规划的？

```
类比: 你要完成毕业设计

差的做法（无规划）:
  随便写代码 → 不知道要写什么 → 推翻重来 → 焦虑 → deadline 到了

好的做法（有规划）:
  1. 调研技术选型（2天）
  2. 搭建基础框架（3天）
  3. 实现核心功能（1周）
  4. 测试和优化（3天）
  5. 写文档（2天）
  → 按步骤执行，有条不紊
```

Agent 的规划机制就是让 LLM 学会"先想后做"。

## 三、Chain of Thought（思维链）

### 3.1 原理

让 LLM 在给出最终答案之前，先展示推理过程。

```
不用 CoT:
  Q: "一个班50人，60%是女生，其中1/3参加了编程社团，多少女生在编程社团？"
  A: "15人"  ← 可能对也可能错，没有中间过程

用 CoT:
  Q: 同上 + "请一步一步思考"
  A: "让我一步步计算：
      1. 总人数：50人
      2. 女生人数：50 * 60% = 30人
      3. 参加编程社团的女生：30 * 1/3 = 10人
      答案：10名女生在编程社团"  ← 推理过程清晰，更容易正确
```

### 3.2 为什么 CoT 有效？

| 原因 | 解释 |
|------|------|
| 分解问题 | 复杂问题拆成小步骤，每步更容易做对 |
| 减少跳跃 | 避免 LLM "直觉式"给出错误答案 |
| 可验证 | 能看到哪一步出错了 |
| 利用上下文 | 每步的结果为下一步提供上下文 |

### 3.3 触发 CoT 的方式

```
方式一: "请一步一步思考"（最简单）
方式二: "Let's think step by step"（英文，论文中最常用）
方式三: 给出推理示例（Few-Shot CoT）
方式四: 模型自带思考 (如 DeepSeek 的 deepseek-reasoner)
```

### 3.4 局限性

- CoT 只在**单次推理**中有效，不涉及工具调用
- 适合：数学推理、逻辑分析、代码调试
- 不适合：需要外部数据的任务（这时候要用 ReAct）

## 四、ReAct 模式（推理 + 行动）—— 最核心！

### 4.1 ReAct 是什么？

ReAct = **Re**asoning + **Act**ing

核心思想：Agent 交替进行"思考"和"行动"，每一步都基于前一步的观察。

```
ReAct 循环:

  Thought: 我需要先查一下北京天气           ← 推理
  Action: get_weather                        ← 行动
  Action Input: {"city": "北京"}
  Observation: 晴天，28度                    ← 观察（工具返回结果）

  Thought: 温度28度，不算很热。用户还问了     ← 基于观察继续推理
           需不需要带伞
  Action: get_weather_forecast               ← 继续行动
  Action Input: {"city": "北京", "hours": 24}
  Observation: 未来24小时无降水

  Thought: 晴天28度，未来无降水，不需要带伞    ← 综合推理
  Final Answer: 北京今天晴天28度，不需要带伞    ← 最终回答
```

### 4.2 为什么 ReAct 是 Agent 的核心？

**ReAct 是目前 Agent 最主流的推理模式**。原因：

| 对比 | 纯 CoT | 纯 Action | ReAct |
|------|--------|-----------|-------|
| 推理能力 | 强 | 无 | 强 |
| 工具使用 | 无 | 有 | 有 |
| 灵活性 | 低 | 低 | 高 |
| 错误恢复 | 差 | 差 | 好（能根据观察调整） |

### 4.3 ReAct 的完整流程图

```
               ┌──────────────────────────────────────┐
               │           ReAct 循环                   │
               └──────────────────────────────────────┘
                              │
                              ↓
               ┌──────────────────────────┐
               │  Thought (思考)           │
         ┌────→│  "我需要做什么？"          │←───────────────┐
         │     └────────────┬─────────────┘                │
         │                  │                              │
         │                  ↓                              │
         │     ┌──────────────────────────┐                │
         │     │  判断: 需要行动还是可以    │                │
         │     │        直接给出答案？      │                │
         │     └────┬──────────────┬──────┘                │
         │          │              │                       │
         │     需要行动         可以回答                     │
         │          │              │                       │
         │          ↓              ↓                       │
         │  ┌──────────────┐ ┌──────────────┐             │
         │  │ Action (行动) │ │ Final Answer │             │
         │  │ 调用工具      │ │ 输出最终答案  │             │
         │  └──────┬───────┘ └──────────────┘             │
         │         │                                      │
         │         ↓                                      │
         │  ┌──────────────┐                              │
         │  │ Observation   │                              │
         │  │ 工具返回结果   │──────────────────────────────┘
         │  └──────────────┘       反馈到下一轮 Thought
         │
         └── 如果还需要更多信息，继续循环
```

### 4.4 ReAct Prompt 模板

```python
REACT_PROMPT = """回答以下问题，你可以使用这些工具：

可用工具：
{tools}

请严格按照以下格式输出：
Thought: [你的推理过程，思考下一步该做什么]
Action: [工具名称]
Action Input: [工具的输入参数]
Observation: [工具返回的结果 - 由系统填写]
... (可以重复 Thought/Action/Observation 多次)
Thought: 我现在有足够的信息来回答了。
Final Answer: [最终答案]

问题：{question}
"""
```

### 4.5 ReAct 在 LangChain 中的实现

```python
from langchain.agents import create_react_agent, AgentExecutor

agent = create_react_agent(llm=llm, tools=tools, prompt=react_prompt)
executor = AgentExecutor(
    agent=agent,
    tools=tools,
    verbose=True,          # 打印完整的 Thought/Action/Observation
    max_iterations=5,      # 最大循环次数
)

# verbose=True 输出示例：
# Thought: 用户问北京天气，我需要调用天气工具
# Action: get_weather
# Action Input: {"city": "北京"}
# Observation: 晴天，28度
# Thought: 已获得天气信息
# Final Answer: 北京今天晴天，28度
```

## 五、Plan-and-Execute（先规划后执行）

### 5.1 原理

与 ReAct 的"边想边做"不同，Plan-and-Execute 先做**完整规划**，然后逐步执行。

```
Phase 1 - 规划:
  用户: "帮我做一份年度销售分析报告"

  LLM Planner 生成计划:
    1. 读取 sales_2024.csv 文件
    2. 按月份汇总销售额
    3. 计算同比增长率
    4. 找出表现最好和最差的月份
    5. 生成趋势图
    6. 撰写分析报告摘要

Phase 2 - 执行:
    Step 1: read_csv("sales_2024.csv") → DataFrame(1000行, 8列)
    Step 2: run_code("df.groupby('month').sum()") → 月度汇总表
    Step 3: run_code("df.pct_change()") → 增长率
    Step 4: run_code("df.idxmax(), df.idxmin()") → 最好6月, 最差2月
    Step 5: save_chart(...) → trend.png
    Step 6: generate_report(...) → 报告文本
```

### 5.2 ReAct vs Plan-and-Execute

| 特性 | ReAct | Plan-and-Execute |
|------|-------|-----------------|
| 规划时机 | 边想边做（每步决策） | 先做完整计划再执行 |
| 灵活性 | 高（随时调整） | 较低（计划确定后不易改） |
| 效率 | 可能走弯路 | 执行路径更直接 |
| 适合 | 探索性任务、信息不完整 | 步骤明确、流程化任务 |
| 类比 | 边走边看地图 | 先规划路线再出发 |

### 5.3 改进：Plan-Replan

更高级的版本允许执行过程中**修改计划**：

```
Plan: [Step1, Step2, Step3, Step4, Step5]
  执行 Step1 → OK
  执行 Step2 → 失败！数据格式不对
  → Replan: 插入 Step2.5 "转换数据格式"
  → 继续执行 [Step2.5, Step2_retry, Step3, Step4, Step5]
```

## 六、Self-Reflection（自我反思）

### 6.1 原理

Agent 生成结果后，让它自己评估结果质量，如果不满意就改进。

```
Step 1: 初次生成
  User: "写一段 FastAPI 的用户注册代码"
  Agent 生成: [一段代码]

Step 2: 自我评估
  Agent 审视自己的代码:
  "这段代码有几个问题：
   1. 没有密码加密
   2. 没有邮箱格式验证
   3. 没有错误处理"

Step 3: 改进
  Agent 根据自己的反馈改进代码:
  [改进后的代码，加了密码加密、验证和错误处理]
```

### 6.2 Reflexion 流程

```
    ┌─────────┐    生成    ┌─────────┐    评估    ┌─────────┐
    │ 任务描述 │ ────────→ │ 初次回答 │ ────────→ │ 反思评价 │
    └─────────┘           └─────────┘           └────┬────┘
                               ↑                     │
                               │     改进建议          │
                               └─────────────────────┘
                                  循环直到满意
```

### 6.3 实现思路

```python
# 伪代码
def self_reflection_loop(task, max_iterations=3):
    response = llm.generate(task)

    for i in range(max_iterations):
        critique = llm.generate(f"评估回答质量，列出问题，评分1-10: {response}")
        if "评分: 8" in critique or "评分: 9" in critique or "PASS" in critique:
            break
        response = llm.generate(f"根据反馈改进: 原回答={response}, 反馈={critique}")

    return response
```

### 6.4 适用场景

| 场景 | 效果 |
|------|------|
| 代码生成 | 自动发现 bug 和改进代码质量 |
| 写作 | 改进文章结构和逻辑 |
| 数据分析 | 验证分析结论是否合理 |
| 数学推理 | 检查计算步骤是否正确 |

## 七、Tree of Thought（思维树）—— 了解即可

### 7.1 简介

CoT 是线性的（一条思考链），Tree of Thought 同时探索多条推理路径：

```
CoT（线性）:
  问题 → 思路A → 步骤1 → 步骤2 → 答案

Tree of Thought（树形）:
  问题 → 思路A → 步骤1 → ...
       → 思路B → 步骤1 → ...    ← 同时探索多个方向
       → 思路C → 步骤1 → ...

  评估每条路径 → 选最好的 → 最终答案
```

- 目前主要在学术研究中使用
- 代价大：需要多次 LLM 调用
- 面试中知道概念即可

## 八、规划模式选择指南

### 8.1 决策树

```
你的任务是什么类型？
│
├── 简单问答（1步完成）
│   └── 不需要规划，直接 Function Calling
│
├── 多步但步骤不确定
│   └── ReAct（边想边做）
│       例: "帮我查一下今天天气，如果下雨就推荐室内活动"
│
├── 多步且流程明确
│   └── Plan-and-Execute（先规划后执行）
│       例: "分析这份数据并生成报告"
│
├── 需要高质量输出
│   └── ReAct + Self-Reflection
│       例: "写一段健壮的用户认证代码"
│
└── 复杂推理
    └── CoT（思维链）
        例: "这道数学题怎么解？"
```

### 8.2 你的项目适合什么？

| 项目 | 推荐模式 | 原因 |
|------|---------|------|
| RAG 知识库 | 简单 Function Calling | 流程固定：检索 → 回答 |
| 数据分析 Agent | Plan-and-Execute | 分析任务有明确步骤 |
| 通用助手 | ReAct | 需要灵活应对各种问题 |

## 九、面试常问

1. **什么是 Chain of Thought？** → 让 LLM 在给出答案前先展示推理过程，通过逐步思考提高复杂任务的准确率
2. **ReAct 是什么，为什么重要？** → Reasoning + Acting 交替的推理模式，Agent 先思考再行动再观察，是目前 Agent 最主流的推理方式
3. **ReAct 和纯 Function Calling 的区别？** → 纯 Function Calling 只是"调用工具"，ReAct 在每步调用前先推理"为什么要调用"和"下一步该怎么做"
4. **Plan-and-Execute vs ReAct？** → Plan-and-Execute 先规划再执行，适合步骤明确的任务；ReAct 边想边做，适合步骤不确定的任务
5. **Self-Reflection 怎么实现？** → 生成结果后让 LLM 自我评估并指出问题，然后根据反馈改进，循环直到质量满意
6. **Tree of Thought 和 CoT 的区别？** → CoT 是线性单链推理，ToT 同时探索多条推理路径选最优的，但计算代价大
7. **Agent 的循环什么时候结束？** → LLM 判断任务完成输出 Final Answer，或达到最大迭代次数限制
8. **你的项目中用了什么推理模式？** → 数据分析 Agent 用 Plan-and-Execute（先规划分析步骤），RAG 项目用简单的 Function Calling（检索+回答流程固定）
