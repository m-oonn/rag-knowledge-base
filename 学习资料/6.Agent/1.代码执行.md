## 一、为什么 Agent 需要执行代码？

LLM 擅长理解需求和生成代码，但它不能直接"运行"代码。需要一个执行环境。

```
用户: "帮我分析sales.csv的月度趋势"
  ↓
LLM 生成代码: df = pd.read_csv('sales.csv'); df.groupby('month')['revenue'].sum()
  ↓
代码执行工具: 在沙箱中运行，捕获输出
  ↓
结果返回给 LLM: "1月: 50000, 2月: 55000, 3月: 48000"
  ↓
LLM 生成报告: "近3个月销售趋势为先升后降..."
```

## 二、exec() vs eval()

| | exec() | eval() |
|--|--------|--------|
| 作用 | 执行任意 Python 代码 | 计算单个表达式 |
| 返回值 | None（输出靠 print） | 表达式的计算结果 |
| 适合 | 多行代码、赋值、循环 | 数学计算、简单表达式 |
| 危险程度 | 高（能做任何事） | 中（不能赋值/导入） |

```python
# eval: 计算表达式
result = eval("2 + 3 * 4")   # result = 14

# exec: 执行代码块
exec("x = 10\nprint(x * 2)")  # 输出 20，但返回 None
```

**Agent 用 exec()**，因为 LLM 生成的是多行代码（导入库、处理数据、打印结果）。

## 三、安全风险与防护

| 风险等级 | 攻击方式 | 防护措施 |
|---------|---------|---------|
| 致命 | `os.system("rm -rf /")` | 移除 os/subprocess 模块 |
| 致命 | `__import__('os').remove(f)` | 清空 `__builtins__` |
| 高 | `while True: pass` | threading.Timer 超时终止 |
| 高 | `[0] * (10**10)` | 资源限制 / subprocess |
| 中 | `requests.get("http://evil.com")` | 移除网络库 |
| 低 | `open("/etc/passwd").read()` | 移除 open 或限制路径 |

### 安全检查清单

```python
# 在 exec 之前检查代码内容
DANGEROUS_KEYWORDS = [
    "import os", "import sys", "import subprocess",
    "__import__", "eval(", "exec(",
    "open(", "file(", "input(",
    "os.system", "os.popen", "subprocess",
    ".remove(", ".rmdir(", "shutil",
]

def is_safe(code: str) -> bool:
    for keyword in DANGEROUS_KEYWORDS:
        if keyword in code:
            return False
    return True
```

## 四、沙箱实现（完整版）

```python
import io
import contextlib
import threading

def safe_exec(code: str, timeout: int = 10, allowed_modules=None) -> dict:
    """
    安全执行代码的完整实现。

    三层防护：
    1. 白名单模块（只允许 pandas/numpy/math）
    2. 超时控制（防止无限循环）
    3. 输出捕获（获取 print 输出和错误信息）
    """
    # 构建安全的全局变量
    safe_globals = {
        "__builtins__": {
            "print": print, "len": len, "range": range,
            "int": int, "float": float, "str": str, "bool": bool,
            "list": list, "dict": dict, "tuple": tuple, "set": set,
            "min": min, "max": max, "sum": sum, "abs": abs, "round": round,
            "sorted": sorted, "enumerate": enumerate, "zip": zip,
            "True": True, "False": False, "None": None,
            "isinstance": isinstance, "type": type,
        }
    }

    # 加载允许的模块
    if allowed_modules is None:
        allowed_modules = ["pandas", "numpy", "math", "json", "datetime"]

    for mod in allowed_modules:
        try:
            m = __import__(mod)
            safe_globals[mod] = m
            # 常用别名
            if mod == "pandas": safe_globals["pd"] = m
            if mod == "numpy": safe_globals["np"] = m
        except ImportError:
            pass

    # 捕获输出
    stdout = io.StringIO()
    result = {"output": "", "error": None, "success": False}

    def run_code():
        try:
            with contextlib.redirect_stdout(stdout):
                exec(code, safe_globals)
            result["output"] = stdout.getvalue()
            result["success"] = True
        except Exception as e:
            result["output"] = stdout.getvalue()
            result["error"] = f"{type(e).__name__}: {e}"

    # 超时控制
    thread = threading.Thread(target=run_code)
    thread.start()
    thread.join(timeout=timeout)

    if thread.is_alive():
        result["error"] = "TimeoutError: Code execution exceeded time limit"
        # 注意：Python 无法真正"杀死"线程，生产环境应该用 subprocess

    return result
```

## 五、错误自修复循环

这是 Agent 的核心竞争力 —— 代码出错后自动修复：

```python
def execute_with_self_repair(llm, user_request, max_retries=3):
    """
    LLM 生成代码 → 执行 → 失败 → LLM 修复 → 重试
    """
    code = llm.generate_code(user_request)

    for attempt in range(max_retries):
        result = safe_exec(code)

        if result["success"]:
            return result

        # 把错误反馈给 LLM，让它修复
        fix_prompt = f"""代码执行失败。
原始代码:
{code}

错误信息:
{result['error']}

请修复代码，只输出修改后的完整代码。"""

        code = llm.chat(fix_prompt)

    return {"error": "Max retries exceeded", "success": False}
```

**面试加分话术**：
> "我的 Agent 有错误自修复能力。代码执行失败后，会把错误信息反馈给 LLM，
> LLM 分析错误原因并修改代码，最多重试 3 次。
> 这模拟了人类程序员'写代码→运行→看报错→修改'的过程。"

## 六、生产环境方案

| 方案 | 安全性 | 实现难度 | 适合场景 |
|------|--------|---------|---------|
| exec + 白名单 | 中 | 低 | 学习/Demo |
| subprocess + timeout | 高 | 中 | 小型项目 |
| Docker 容器 | 极高 | 高 | **生产环境** |
| 云函数（AWS Lambda） | 极高 | 高 | 大规模部署 |

你的项目用 "exec + 白名单" 就够了。面试时提到 Docker 方案表示你知道生产级做法。

## 七、面试常问

1. **Agent 怎么执行代码？** → LLM 生成代码字符串，用 exec() 在受限沙箱中执行，捕获 stdout/stderr
2. **怎么防止恶意代码？** → 清空 `__builtins__`，白名单允许模块，关键词过滤，超时终止
3. **exec 和 eval 的区别？** → exec 执行任意代码无返回值，eval 计算表达式有返回值
4. **执行失败怎么办？** → 捕获错误信息反馈给 LLM，LLM 修正代码重新执行（自修复循环，最多3次）
5. **生产环境怎么做代码执行？** → 用 Docker 容器隔离，每次执行创建临时容器，执行完销毁
