# Day 43：状态管理

> Agent 需要跟踪每一步的结果和进度。LangGraph 的 State + Checkpoint 是标准方案。

---

## 一、为什么需要状态管理？

```
没有状态管理的 Agent：
  Step 1: 读取数据 → "200行5列"
  Step 2: 分析数据 → "等等，数据在哪？我忘了..." ← 失忆！

有状态管理的 Agent：
  State = {data: DataFrame, results: [...], step: "analyzing"}
  Step 1: 读取数据 → state.data = df
  Step 2: 分析数据 → 从 state.data 读取 → state.results.append(分析结果)
  Step 3: 生成图表 → 从 state.results 读取 → state.charts.append(图表路径)
```

Agent 的状态就像人的"工作记忆"—— 记住你做了什么、正在做什么、还要做什么。

## 二、LangGraph State 设计

### 2.1 TypedDict 定义状态

```python
from typing import TypedDict, Annotated
from langgraph.graph import add_messages

class DataAnalysisState(TypedDict):
    """数据分析 Agent 的状态定义"""
    # 对话历史（add_messages 是 reducer，自动追加不覆盖）
    messages: Annotated[list, add_messages]
    # 当前阶段
    current_step: str          # "loading" / "analyzing" / "charting" / "reporting"
    # 数据相关
    file_path: str             # 用户上传的文件路径
    data_summary: str          # 数据概览（列名、类型、前几行）
    # 分析结果
    analysis_results: list     # 每步分析的结果
    chart_paths: list          # 生成的图表路径
    # 控制
    error_count: int           # 错误次数（用于判断是否重试）
    final_report: str          # 最终报告
```

### 2.2 Reducer 的作用

```python
# 普通字段：后面的值覆盖前面的
state["current_step"] = "analyzing"  # 直接覆盖

# 带 add_messages reducer 的字段：追加而不是覆盖
state["messages"] = [new_message]  # 自动追加到已有列表后面

# 这就是为什么对话历史不会被覆盖
```

### 2.3 Node 函数怎么用 State

```python
def analyze_node(state: DataAnalysisState) -> dict:
    """
    每个 Node 函数：
    - 接收完整 state
    - 返回要更新的部分（不需要返回不改的字段）
    """
    data_summary = state["data_summary"]
    # ... 做分析 ...

    return {
        "current_step": "charting",           # 更新当前步骤
        "analysis_results": [new_result],     # 追加结果
        "messages": [AIMessage(content="分析完成")],
    }
```

## 三、Checkpoint（检查点）

### 3.1 为什么需要 Checkpoint？

- Agent 执行到一半服务器重启了 → 从上次保存点恢复
- 用户关了浏览器明天再来 → 恢复之前的对话和分析进度
- 需要回退到之前的步骤 → 从历史 checkpoint 恢复

### 3.2 Checkpoint 类型

| 类型 | 存储位置 | 适合场景 | 持久性 |
|------|---------|---------|--------|
| MemorySaver | 内存 | 开发测试 | 程序退出就没了 |
| SqliteSaver | SQLite文件 | 小型项目 | 持久化到磁盘 |
| PostgresSaver | PostgreSQL | 生产环境 | 持久化+多实例 |

### 3.3 使用 Checkpoint

```python
from langgraph.checkpoint.memory import MemorySaver

# 创建 checkpointer
checkpointer = MemorySaver()

# 编译 graph 时传入
app = workflow.compile(checkpointer=checkpointer)

# 调用时指定 thread_id
config = {"configurable": {"thread_id": "user_123"}}
result = app.invoke({"messages": [user_message]}, config=config)

# 同一个 thread_id 再次调用 → 自动恢复之前的状态
result2 = app.invoke({"messages": [follow_up]}, config=config)
# ↑ state 中保留了之前的对话历史和分析结果
```

### 3.4 多用户隔离

```python
# 用户 A 的分析状态
config_a = {"configurable": {"thread_id": "user_alice_task_1"}}
app.invoke(input_a, config=config_a)

# 用户 B 的分析状态（完全独立）
config_b = {"configurable": {"thread_id": "user_bob_task_1"}}
app.invoke(input_b, config=config_b)

# 每个 thread_id 有自己独立的 state 和 checkpoint
# 互不干扰
```

## 四、State 设计最佳实践

### 4.1 状态要精简

```python
# 不好：把整个 DataFrame 放在 state 里
state["dataframe"] = df  # 可能几百MB，序列化很慢

# 好：只放必要的信息
state["data_summary"] = df.describe().to_string()  # 几KB
state["file_path"] = "/uploads/sales.csv"           # 需要时重新读取
```

### 4.2 结果要累积

```python
# 不好：每步覆盖结果
state["result"] = "最新结果"  # 之前的结果丢了

# 好：累积到列表
state["results"].append({"step": "analyze", "output": "最新结果"})
```

### 4.3 控制信息要记录

```python
state["error_count"] = 0       # 用于判断是否超过重试上限
state["current_step"] = "init" # 用于条件路由
state["needs_chart"] = True    # 用于决定是否跳过图表节点
```

## 五、面试常问

1. **Agent 怎么管理状态？** → LangGraph 用 TypedDict 定义 State，每个 Node 读取并更新 State，State 在图的边上流动
2. **Checkpoint 是什么？** → 自动保存 Agent 每步执行后的状态快照。中断后可以用 thread_id 从快照恢复继续执行
3. **多用户怎么隔离？** → 每个用户分配唯一 thread_id，Checkpoint 按 thread_id 独立存储
4. **Reducer 是什么？** → 控制 State 字段更新方式的函数。如 add_messages 让 messages 字段追加而不覆盖
5. **State 里应该放什么？** → 必要的控制信息+中间结果摘要。不放大数据（DataFrame），放路径需要时重新读取
