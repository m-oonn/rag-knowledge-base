# Day 42：多工具协调

> Agent 的真正威力：在多个工具间自主切换，编排复杂工作流，并从错误中恢复。

## 一、从单工具到多工具

```
单工具 Agent（简单）:
  用户 → LLM → 调用1个工具 → 返回结果

多工具 Agent（你的项目）:
  用户 → LLM → 选工具1 → 选工具2 → 选工具3 → 汇总 → 返回结果
  "分析销售趋势画个图" → read_csv → analyze → create_chart → write_report
```

多工具协调的核心问题：**谁来决定用哪个工具、什么顺序、怎么处理失败？**

答案：**LLM 自己决定**（通过 Function Calling）或 **开发者预定义工作流**（通过 LangGraph）。

## 二、工具注册模式

```python
class ToolRegistry:
    """工具注册中心：所有工具在这里注册和发现"""

    def __init__(self):
        self.tools = {}

    def register(self, name, description, func, params_schema=None):
        self.tools[name] = {
            "name": name,
            "description": description,  # 给 LLM 看的描述
            "func": func,
            "schema": params_schema,
        }

    def get_tool_descriptions(self) -> str:
        """生成给 LLM 的工具列表（放在 Prompt 里）"""
        lines = []
        for name, tool in self.tools.items():
            lines.append(f"- {name}: {tool['description']}")
        return "\n".join(lines)

    def call(self, name, **kwargs):
        return self.tools[name]["func"](**kwargs)
```

LLM 看到工具描述后，根据用户需求决定调用哪个。描述写得好不好**直接影响 Agent 准确率**。

## 三、工具链编排策略

### 3.1 线性链

```
read_data → analyze → chart → report

适合：流程固定的任务（数据分析的主要模式）
实现：按顺序调用，前一步结果传给下一步
```

### 3.2 条件链

```
read_data → analyze → 需要图表？─ Yes → chart ─→ report
                                  └ No ──────────→ report

适合：部分步骤可选的任务
实现：LangGraph 条件边，或 if/else 判断
```

### 3.3 循环链（错误自修复）

```
generate_code → execute → 成功？─ Yes → 使用结果
                            └ No → fix_code → 回到 execute
                                  （最多3次）

适合：代码执行类任务（你的项目二核心）
实现：LangGraph 循环边 + 计数器
```

### 3.4 在 LangGraph 中实现

```python
from langgraph.graph import StateGraph, END

workflow = StateGraph(AgentState)

# 添加节点
workflow.add_node("load", load_data_node)
workflow.add_node("analyze", analyze_node)
workflow.add_node("chart", chart_node)
workflow.add_node("report", report_node)

# 线性连接
workflow.add_edge("load", "analyze")

# 条件连接
workflow.add_conditional_edges("analyze", should_create_chart,
    {"yes": "chart", "no": "report"})

workflow.add_edge("chart", "report")
workflow.add_edge("report", END)
```

## 四、工具选择的两种模式

| 模式 | 决策者 | 优点 | 缺点 | 适合 |
|------|--------|------|------|------|
| LLM 自主选择 | LLM | 灵活，适应新需求 | 可能选错 | 开放式对话 |
| 预定义工作流 | 开发者 | 可靠，可控 | 不灵活 | 固定流程任务 |
| **混合模式** | 两者 | 兼顾灵活和可控 | 实现复杂 | **你的项目** |

你的项目二推荐**混合模式**：主流程由 LangGraph 预定义（load→analyze→chart→report），但具体分析步骤由 LLM 自主决定（用什么 pandas 操作、画什么类型的图）。

## 五、错误恢复策略

| 策略 | 实现 | 适用场景 |
|------|------|---------|
| 重试 | 相同参数再调一次 | 网络超时、随机错误 |
| 修改参数重试 | LLM 调整参数 | 参数错误（如列名拼错）|
| 换工具 | 用替代工具 | 某工具不可用 |
| 跳过 | 标记失败，继续后面的步骤 | 非关键步骤失败 |
| 上报用户 | 告诉用户哪里失败了 | 无法自动恢复 |

```python
def execute_with_recovery(tool_name, args, registry, max_retries=2):
    """带恢复策略的工具调用"""
    for attempt in range(max_retries + 1):
        result = registry.call(tool_name, **args)
        if "[FAIL]" not in result:
            return result  # 成功

        if attempt < max_retries:
            # 策略1: 修改参数
            if "encoding" in result:
                args["encoding"] = "gbk"
            # 策略2: 换替代工具
            elif "not found" in result and tool_name == "read_csv":
                tool_name = "read_excel"

    return f"Failed after {max_retries + 1} attempts: {result}"
```

## 六、面试常问

1. **Agent 怎么决定用哪个工具？** → LLM 根据 tool description 和 user request 自主选择（Function Calling 机制）
2. **工具调用失败怎么办？** → 分策略：重试、修改参数、换工具、跳过、上报用户。优先自动恢复
3. **多工具之间怎么传递数据？** → 通过 LangGraph State，前一个工具的输出存入 state，后一个工具从 state 读取
4. **预定义工作流和 LLM 自主选择哪个好？** → 混合模式最好：主流程预定义保证可控，具体步骤 LLM 决策保证灵活
5. **你的数据分析 Agent 用了哪些工具？** → read_data、analyze、execute_code、create_chart、write_report，用 LangGraph 编排
